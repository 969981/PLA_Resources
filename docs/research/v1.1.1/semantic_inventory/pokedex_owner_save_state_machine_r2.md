## 1. 图鉴状态指针的持有者：确认的上层槽位

**OBSERVED — `FUN_01148F20`，`c/01/01148f20.c`：**

1. 从 `context + 0x298` 读取一个指针，并将其写入输出参数 `*param_1`。
2. 对该对象的 `+0x58` 所指控制结构进行有效性检查。
3. 如控制结构 `+0x10` 尚未构造，调用 `+0x18` 保存的初始化工厂。
4. 对相关控制结构 `+0x0C` 处计数器执行原子递增。

**OBSERVED — `FUN_010A5218`，`c/01/010a5218.c`：**

它依次读取 `context +0x58, +0x88, +0xB8, ... +0x298, +0x2C8, +0x2F8, +0x328`，检查对应对象 `+0x1E1` 是否就绪；只有相关资源就绪才继续执行初始化阶段 `FUN_010A4724` 并更新 `context+0x4F78/+0x4F79`。

**OBSERVED — `FUN_01906830`，`c/01/01906830.c`：**

它通过全局上下文 `PTR_DAT_04379560` 获取 `lVar15`，依次调用：

- `FUN_01148B80(..., lVar15)` → 读 `+0x240`
- `FUN_01148F20(..., lVar15)` → 读 `+0x298`
- `FUN_01148EAC(..., lVar15)` → 读 `+0x288`

**OBSERVED — `FUN_00E62390`，`c/00/00e62390.c`：**在名为 `SaveSystem` 的原生绑定组中登记 `PokedexSave` 与 `EventWork`、`MyItem` 等接口名称。

**INFERRED：** `+0x298` 很可能是持有图鉴状态的受管理对象槽位（或它的代理）。仅靠一致偏移和名称，尚不能证明该槽位等同于最终磁盘存档的某段原始字节；仍需找槽位写入者、对象实际分配大小及序列化映射。

## 2. 真实文件提交路径与阶段状态

**OBSERVED — `FUN_011457E4`，`c/01/011457e4.c`：**

- `param_1[1]==0`：调用 `FUN_01148354` 创建/打开任务，再调用 `FUN_01148558`，将阶段设为 `1`。
- `param_1[1]==1`：调用 `FUN_011485C0`，尚未就绪则直接返回；就绪后依次调用 `FUN_01148628`（结果写入 `param_1[2]`）、`FUN_01148690`（提交包装）、`FUN_011486F8`（回调与释放），再将阶段设为 `2`。
- 阶段 `2` 说明这条工作流的执行阶段已经走到尾声，但并不自动代表磁盘持久化成功。

**OBSERVED — `FUN_011485C0` → `FUN_0114FB20`：**

该路径返回底层作业对象 `+0x302` 字节的 bit 0；更合理的候选名称是 `IsJobReady`，而不是 `IsSaveCommitted`。

**OBSERVED — `FUN_01148628` → `FUN_0114FB40`：**

在底层对象的 `+0x478` 互斥锁下读取 `+0x470` 的 u32 值。该值是**可读出的任务状态/结果字段**，其业务枚举意义和是否包含提交错误尚待验证。

**OBSERVED — `FUN_01148690`：**

在上层 `+0x180` 互斥锁内确认 `+0x160` 任务指针及标识条件后调用 `FUN_02A8F2F4(param_1+0xA8)`，再返回 `1`。其返回的 `1` 不是直接传播底层 `Commit` 的错误码。

**OBSERVED — `FUN_02A8F2F4`，`c/02/02a8f2f4.c`：**

调用 `nn::fs::Commit(mount_name)`，并把返回值写入任务状态对象的一个结果字段（代码为 `*(undefined4 *)(param_1+1) = uVar1`，即传入指针之后的 +0x08）。同时设置结果类型/阶段字段。该函数**确实调用文件系统 Commit**，但是其输出仍需要通过调用方和作业状态闭环追踪。

**OBSERVED — `FUN_011486F8`：**

重新调用 `FUN_01148628`，如果登记了 `context+0x1A0` 回调，则传入布尔值 `(result==2)`；随后执行清理并清零 `context+0x160`。该布尔值是**回调判断结果**，在没有追查结果产生者之前不能直接称为 `Commit ACK`。

**证据空缺：**目前没有证明 `FUN_0112F528` 写入的图鉴状态如何送入这个作业的序列化缓冲区，更未证明 `FUN_011486F8` 的状态值 `2` 对应成功保存的完整定义。
